# Участие в разработке

Прежде чем вносить изменения, обсудите их в issue.

Обратите внимание: у проекта есть [кодекс поведения](CODE_OF_CONDUCT.md), соблюдайте его во всём общении в проекте.

## Процесс pull request

1. Никогда не коммитьте секреты и реальные данные инфраструктуры: файлы `.env`, ключи REALITY, сертификаты, базы данных, реальные IP-адреса и домены. Используйте плейсхолдеры `<ip_master>`, `<ip_slave>`, `<master_domain>`, `<slave_domain>`. Личные доработки держите в `local/` и `local.mk` (они в `.gitignore`).
2. Скрипты пишите на POSIX `sh` и делайте идемпотентными; проверяйте изменённые скрипты `sh -n` (и `shellcheck`, если есть).
3. Проверяйте на реальной паре master + slave: `make master-status`, `make slave-status`, статус ноды `connected` в панели и подключение клиента через каждый сервер.
4. Меняете поведение, переменные окружения, порты или цели — обновите README.md и docs/. Документация пишется на русском.
5. При обновлении образов Marzban / Marzban Node / Caddy закрепляйте тег и digest и указывайте в PR проверенные версии.
6. Pull request вливается после ревью и одобрения мейнтейнера.

## Кодекс поведения

В проекте действует [Кодекс поведения](CODE_OF_CONDUCT.md) (Contributor Covenant 2.1). Участвуя, вы соглашаетесь его соблюдать. О нарушениях сообщайте на github@imtrim.dev.

## Уязвимости

Не публикуйте уязвимости в issues и pull requests — следуйте [политике безопасности](SECURITY.md).
