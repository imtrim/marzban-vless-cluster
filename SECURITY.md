# Политика безопасности

## Поддерживаемые версии

| Версия | Поддерживается |
|---|---|
| ветка `main` (последний коммит) | да |
| старые коммиты, форки | нет |

Релизов пока нет; исправления выходят только в `main`.

## Как сообщить об уязвимости

**Не создавайте публичный issue, discussion или pull request с описанием уязвимости.**

Сообщите приватно одним из способов:
- через GitHub: вкладка **Security → Report a vulnerability** (private vulnerability reporting);
- по почте: github@imtrim.dev.

В сообщении укажите:
- что именно уязвимо (файл, скрипт, цель Makefile, настройка);
- как воспроизвести и к чему это приводит;
- версию (хеш коммита) и окружение (ОС, версии Docker и образов).

**Удалите из отчёта** реальные IP-адреса, домены, ключи REALITY, UUID пользователей, ссылки подписок, пароли, токены и сертификаты. Замените их на плейсхолдеры (`<ip_master>`, `<master_domain>` и т. п.).

## Чего ожидать

Проект поддерживается одним человеком в свободное время, поэтому сроки не гарантируются. Ориентировочно:
- подтверждение получения — в течение нескольких дней;
- оценка и план исправления — по мере возможности;
- после исправления — коммит в `main` и, если вы не против, упоминание в описании изменения.

Пожалуйста, не раскрывайте детали публично, пока исправление не опубликовано или пока мы не договорились об ином.

## Область действия

**Входит:**
- скрипты, `Makefile`, compose-файлы, `Caddyfile`, шаблон конфига Xray и правила фаервола из этого репозитория;
- небезопасные значения по умолчанию и ошибки в документации, которые ведут к утечке данных или открытым портам (например, панель или API ноды доступны снаружи).

**Не входит** — сообщайте в соответствующий проект:
- уязвимости самого Marzban и Marzban Node: [Gozargah/Marzban](https://github.com/Gozargah/Marzban), [Gozargah/Marzban-node](https://github.com/Gozargah/Marzban-node);
- уязвимости Xray-core и REALITY: [XTLS/Xray-core](https://github.com/XTLS/Xray-core);
- уязвимости Caddy: [caddyserver/caddy](https://github.com/caddyserver/caddy);
- Docker, ядро Linux, ОС и инфраструктура хостера;
- блокировки IP и обнаружение протокола средствами DPI/ТСПУ — это не уязвимость проекта (см. [предупреждения](docs/warnings.md));
- проблемы конфигурации конкретного сервера, не вызванные этим репозиторием.
